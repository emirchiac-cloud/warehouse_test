Unified Inventory Management System

1. Project Overview & Scenario

Your team has been contracted to build a Full-Stack Unified Inventory Management & Stock Control System for a growing retail and warehouse operation. Currently, warehouse floor staff and back-office managers struggle with out-of-sync spreadsheets and delayed stock counts.

To solve this, you will architect a single centralized PHP & MySQL backend that simultaneously powers two client applications:

  1. The Back-Office Web Portal (Bootstrap 5 + PHP): Used by managers to oversee inventory valuation, manage product categories, review audit logs, perform full CRUD operations, and generate official PDF and Excel reports.
  2. The Warehouse Floor Mobile App (Native Android): Used by warehouse staff on the floor to quickly look up products with cached imagery, register newly arrived inventory using device photos, adjust stock counts in real time (+ / −), and receive immediate hardware alerts (vibration + system notification) when an item drops below its safe minimum threshold.
Both platforms must connect to the exact same MySQL database and shared image storage folder in real time.

3. Detailed Functional & Technical Specifications

Part A: Relational Database Architecture (MySQL)

Design and implement a normalized relational database named inventory_system containing at least the following tables:

1. users

  • id (INT, PK, Auto-Increment)
  • username (VARCHAR, UNIQUE)
  • password_hash (VARCHAR — bcrypt/Argon2 hashed)
  • role (ENUM: 'admin', 'staff')
  • created_at (TIMESTAMP)

2. categories

  • id (INT, PK, Auto-Increment)
  • name (VARCHAR, UNIQUE)
  • description (TEXT)

3. products

  • id (INT, PK, Auto-Increment)
  • category_id (INT, FK → categories.id)
  • name (VARCHAR)
  • description (TEXT)
  • unit_price (DECIMAL 10,2)
  • quantity (INT)
  • min_stock_threshold (INT — triggers low-stock alert when quantity < min_stock_threshold)
  • image_path (VARCHAR — stores relative path, e.g., uploads/products/item_101.jpg)
  • updated_at (TIMESTAMP)

4. stock_logs (Audit Trail)

  • id (INT, PK, Auto-Increment)
  • product_id (INT, FK → products.id ON DELETE CASCADE)
  • user_id (INT, FK → users.id)
  • action_type (ENUM: 'CREATED', 'STOCK_IN', 'STOCK_OUT', 'UPDATED', 'DELETED')
  • quantity_change (INT — positive for IN, negative for OUT)
  • timestamp (TIMESTAMP)
  • notes (TEXT)

Part B: REST API Endpoints (PHP)

Method Endpoint Description Auth Required
POST /api/auth.php Login — returns JWT/session token No
GET /api/products.php List all products (joined with category); supports ?category_id=X and ?search=keyword Yes
POST /api/products.php Create product with multipart image upload (JPG/PNG/WEBP, max 5 MB) Admin
PUT /api/products.php Update product details and/or image; logs UPDATED Admin
DELETE /api/products.php Delete product record and image file; logs DELETED Admin
PUT /api/stock.php Adjust stock (+/−); logs STOCK_IN or STOCK_OUT Yes
GET /api/logs.php Return paginated audit log with filters Admin

Part C: Web Portal Features (Bootstrap 5 + PHP)

1. Authentication & Session Management

  • Secure login with PHP sessions; passwords hashed with password_hash() (bcrypt).
  • Role-based access: Admin can CRUD products & view logs; Staff can view and adjust stock only.
  • All PDO/MySQLi queries must use prepared statements to prevent SQL injection.

2. Dynamic PDF Export (Dompdf or mPDF)

Create a "Download Valuation & Low-Stock PDF" button. The generated PDF must include:

  • Company/System header, generation date/time, name of the logged-in user who generated it.
  • A styled table of inventory items with embedded product thumbnail images, unit price, quantity, subtotal value.
  • Highlighted rows for items below min_stock_threshold.
  • A Grand Total Valuation footer.

3. Dynamic Excel Export (PhpSpreadsheet)

  • Create a "Download Excel Report (.xlsx)" button.
  • The exported file must contain styled headers, all product rows from the filtered/searched view, and a SUM formula for total inventory value.
  • Support optional filtering by category before export.

4. Live Inventory Dashboard

  • Paginated, searchable, filterable product table with low-stock visual indicators (red badge).
  • Inline stock adjustment (+/−) with real-time row refresh via AJAX.
  • Category management panel (Add/Edit/Delete categories).
  • Audit log viewer with filters (by user, date range, action type).

Part D: Android Mobile App (Native Java/Kotlin)

1. Authentication & Session Persistence

  • Login screen posting credentials to /api/auth.php via Retrofit.
  • Store returned token/session in SharedPreferences; auto-login on subsequent launches.

2. Product List with Picasso Image Loading

  • Fetch products asynchronously via Retrofit (GET) and bind JSON to a RecyclerView.
  • Use Picasso to load each product's remote image URL with .placeholder(), .error(), and .resize()/.centerCrop().
  • Visually distinguish low-stock items (e.g., red badge or tinted border when quantity < min_stock_threshold).

3. Register New Inventory (POST Multipart Upload)

  • Provide an "Add Product" Activity via a Floating Action Button (FAB).
  • Capture a product photo using the device camera (ACTION_IMAGE_CAPTURE Intent).
  • Submit product fields + image as a Retrofit @Multipart request.

4. Item Detail, Quick Stock Count & Deletion

  • Tapping any RecyclerView item launches a Product Detail / Edit Activity via explicit Intent.
  • Include quick +1 and −1 stock adjustment buttons sending async PUT requests.
  • Include a Delete Product button with confirmation AlertDialog sending async DELETE.

5. Hardware Feedback & Low-Stock Alerts

When a stock adjustment causes quantity < min_stock_threshold:

  1. Trigger the Android Vibrator / VibratorManager service for 500 ms.
  2. Fire a local Android System Notification (NotificationCompat.Builder) with title "Low Stock Warning" and message "[Product Name] is down to [X] units (Minimum: [Y]). Reorder required."
